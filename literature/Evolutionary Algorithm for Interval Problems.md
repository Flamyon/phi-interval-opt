# [7] Cui et al. 2024 — Evolutionary Algorithm for Interval Problems

## 1. Core claim (2–3 sentences)
The paper proposes IMEA-IED (Interval Many-objective Evolutionary Algorithm with Information Entropy Dominance), an NSGA-III-style algorithm built to solve interval many-objective optimization problems (IMaOPs — more than three conflicting objectives with interval-valued parameters). Its central contribution is a dominance rule that adaptively weighs "convergence" (interval midpoint) versus "uncertainty" (interval width) using information entropy, rather than using a single fixed rule for every comparison. It also modifies the niche-selection step of NSGA-III with two new mechanisms (a crowding-distance-increment tiebreaker and an adaptive reference-vector update) to handle the fact that interval-valued individuals don't partition into reference-vector niches as cleanly as point-valued ones.

## 2. How they represent interval objectives
They do **not** transform intervals into a single real number before optimization. Objectives stay interval-valued throughout the run: each objective $f_i(\mathbf{x}, C_i)$ is an interval $[\underline{f_i}, \overline{f_i}]$, and interval arithmetic (interval addition, subtraction, multiplication, division, scalar multiplication, norm) is used wherever objective values must be combined (Eq. 2–3). Comparison between two interval-valued objectives is handled by their custom interval dominance method (IDM) described below — this is applied *inside* the non-dominated sorting step, replacing ordinary numeric `≤` comparisons. So the whole NSGA-III pipeline (sorting, niching, reference-vector association) is re-derived to accept interval inputs directly rather than converting the problem into a deterministic multi-objective problem first.

## 3. Their dominance relation for intervals
Two intervals $a=[\underline a,\overline a]$, $b=[\underline b,\overline b]$ are compared via an **adaptive, entropy-gated confidence rule**, not a fixed formula. For each objective $k$ across the whole population they first compute two population-level entropies:

- Convergence entropy $H_{ck}$, built from the proportions $p_{ckj} = m(f_k(\mathbf{x}_j)) / \sum_j m(f_k(\mathbf{x}_j))$ of interval **midpoints** $m(\cdot)$.
- Uncertainty entropy $H_{wk}$, built the same way from interval **widths** $w(\cdot)$.

Then, for any pair $a,b$ on objective $k$:
- If $H_{ck} < H_{wk}$ (midpoints are more "unstable"/informative across the population), use the convergence-based confidence
$$P_c(a\le b)=\max\Big\{1-\max\Big[\tfrac12+\tfrac{m(a)-m(b)-\Delta m}{w(a)+w(b)},0\Big],0\Big\},\quad \Delta m=m(b)-m(a)$$
- If $H_{ck} > H_{wk}$, use the analogous width-based confidence $P_w(a\le b)$ with $\Delta w = w(b)-w(a)$ substituted in place of $\Delta m$.
- If $H_{ck}=H_{wk}$, fall back to the plain (non-adaptive) confidence rule IDM3 (Eq. 8).

$P>0.5$ (loosely, above the threshold $\gamma$) means $a$ dominates $b$; $P<0.5$ (below $1-\gamma$) means $b$ dominates $a$; values in between are non-dominated. This is then plugged into a standard Pareto-dominance definition (Eq. 10): $\mathbf{x}\prec\mathbf{y}$ iff every objective interval of $\mathbf{x}$ dominates-or-ties that of $\mathbf{y}$ under IDM, and at least one strictly dominates.

**How this differs from standard real-valued Pareto dominance:** ordinary Pareto dominance requires $f_i(x) \le f_i(y)$ for all $i$ with strict inequality somewhere — a crisp, non-probabilistic per-objective test on real numbers. Here, because objectives are intervals that can overlap, cross, or nest (their Fig. 2's Cases A/B/C), a crisp `≤` often can't be evaluated, so they replace it with a *confidence degree* $P\in[0,1]$ against an adaptive threshold, and which "aspect" of the interval (midpoint vs. width) governs that confidence changes generation-to-generation and objective-to-objective based on entropy. So it's dominance-under-uncertainty with a data-driven, non-stationary switching rule, not a fixed comparator.

## 4. Algorithm structure
The backbone is NSGA-III (population init with uniform reference vectors → offspring via binary crossover + polynomial mutation → merge parent+offspring → non-dominated sort → fill next generation front-by-front → niche selection for the last front → repeat until $t_{max}$). Their two modifications:
- **Standard/unmodified**: binary crossover, polynomial mutation, front-by-front filling of $P_{t+1}$, overall generational loop (Algorithm 1).
- **Modified — dominance step**: ordinary Pareto/point non-dominated sorting is replaced by the information-entropy interval dominance method (Algorithm 2) described in Section 3 above.
- **Modified — niche selection** (Algorithm 3, "adaptive niche selection strategy"): instead of NSGA-III's plain niche-count tiebreak, they (a) associate last-front solutions to reference vectors via perpendicular distance $d_2$ (computed with interval arithmetic), (b) when several subpopulations tie on niche count, break the tie using a **crowding-distance-increment** ($CI(i)=C_t(i)-C_{t-1}(i)$, favoring subpopulations whose crowding distance is still growing), and (c) if the selected subpopulation's reference vector has no associated solution left in the current front, they **temporarily relocate** the reference vector (midpoint between it and a neighboring vector, Eq. 25) to try to recover a usable solution before giving up on that vector for the generation.

## 5. Benchmark problems used
All problems are transformed from deterministic multi-objective test suites into interval versions ("InWFG", "InDTLZ") by adding a perturbation $c_i = \lambda|\sin(10i\pi\sum_j x_j)|\, f_i(\mathbf{x})$ to each objective (Eq. 26–27, $\lambda=0.1$), so every listed problem has interval uncertainty by construction. Each is run at 5, 8, 10, and 15 objectives (population sizes 212/156/276/136 respectively, or 210/156/275/135 for the decomposition-based competitors) for 1000 generations, 20 independent runs:

| Problem family | Members tested | Objectives tested | Interval? | Reported result (qualitative) |
|---|---|---|---|---|
| InWFG | WFG1–WFG9 (9 problems) | 5, 8, 10, 15 | Yes (all) | IMEA-IED best IIGD on InWFG4–7 (concave/linear-ish fronts); best on InWFG1 (sharp-tail) at 5,8 obj but loses to decomposition-based IMOEA/D-AWN at 15 obj; best on InWFG2 at 5,8 obj, loses to IMOEA/D-AWN at 10,15 obj; loses to EG-IMOEA/IMOEA/D/IMOEA-D-AWN on InWFG3 (degenerate front) |
| InDTLZ | DTLZ1–DTLZ6 (6 problems) | 5, 8, 10, 15 | Yes (all) | IMEA-IED best IIGD on InDTLZ1–4; loses to IMOEA/D on InDTLZ5–6 (degenerate fronts, where decomposition + neighborhood crossover helps convergence) |
| Practical application: IMaOWMUE (interval many-objective workflow migration in edge computing, from a separate cited paper) | 1 problem, 4 objectives: migration delay, max completion time, energy consumption, load balancing | 4 | Yes | IMEA-IED ranks 1st on HV, Spread, and Runtime among 8 algorithms; 2nd-best (after SetGA) on Imprecision |

Four metrics used across all of the above: IIGD (Interval Inverse Generational Distance — convergence+diversity vs. the deterministic Pareto front), Spread (uniformity of distribution), Imprecision (average "size" of the interval solution set — smaller = less uncertain), and Runtime.

## 6. What they compare against
Seven competing interval evolutionary algorithms: **IMOEA** (Gong et al., maximal-interval-confidence dominance, IDM1), **SetGA** (Gong et al., set-based GA that converts IMaOPs to a bi-objective hypervolume/uncertainty problem), **DI-μMOGA** (Liu & Liu, interval probability / non-dominated sorting), **InMaOEA** (Zhang et al., cloud-task-scheduling-oriented interval many-objective EA), **IMOEA/D** (Gan et al., decomposition-based, adaptive reference vectors), **EG-IMOEA** (their own prior work, elite-genetic-strategy interval EA using conditional interval confidence, IDM2), and **IMOEA/D-AWN** (Jin et al., decomposition with adaptive weight-vector/neighborhood adjustment). Metrics: IIGD, Spread, Imprecision, Runtime (benchmarks); Hypervolume (HV), Imprecision, Spread, Runtime (practical application). Statistical comparisons use the Wilcoxon rank-sum test (+/−/= counts against IMEA-IED).

## 7. Their key result
Across 60 InWFG/InDTLZ benchmark problems, IMEA-IED wins outright or ties on IIGD in the majority of concave/linear-front problems (InWFG4–7, InDTLZ1–4) and is competitive (though not always best) elsewhere, while also achieving the lowest or near-lowest Imprecision and the shortest runtime among all dominance-based (non-decomposition) competitors. The paper frames this as evidence that **adaptively switching between convergence-focused and uncertainty-focused interval comparison (via entropy) beats any single fixed interval dominance rule** — this is directly supported by their own ablation (Table 10/11, Fig. 7): the adaptive IDM (with information entropy) beats both the convergence-only and uncertainty-only fixed variants on the metric each fixed variant "sacrifices," and beats the traditional non-adaptive IDM3 on both IIGD and Imprecision simultaneously. Its weak spots are consistent and are honestly reported: decomposition-based methods (IMOEA/D, IMOEA/D-AWN) beat it on degenerate/sharp-tail high-objective-count fronts (InWFG1 at 15 obj, InWFG2 at 10–15 obj, InDTLZ5–6), which they attribute to niche-selection weakening as objective count grows and to decomposition being intrinsically better suited to degenerate geometries.

## 8. How your project relates to this
Structurally, this is the "second type" of interval optimization method the paper itself contrasts against in its introduction: Cui et al. operate directly on intervals, building a custom dominance relation and modified NSGA-III machinery so the algorithm itself understands interval uncertainty, whereas your project's approach (fix a φ-automorphism, transform the interval problem into a real multi-objective one, then run off-the-shelf NSGA-II/PSO via pymoo) is the "first type" — an indirect/transformation-based method, which Cui et al. explicitly claim "loses interval information" relative to their direct approach. A fair comparison would not be "whose Pareto front is better" in isolation, since the two methods are answering different questions: theirs asks "what is the best interval dominance rule to use directly," while yours asks "how sensitive are solutions to the choice of φ, holding the optimizer and interval-order-to-real-objective machinery fixed." A meaningful cross-comparison would need to run both on the same InWFG/InDTLZ (or IMaOWMUE) benchmarks, using the same population sizes/generations/perturbation model, and compare IIGD/Spread/Imprecision — at which point you'd learn whether any single φ-induced transformation approaches the entropy-adaptive direct dominance method, or whether the "cost" of discarding interval information via φ is small enough to be worth the simplicity of reusing standard NSGA-II/PSO.

## 9. Flags
- The paper never gives an explicit, closed-form general definition of $d(b,\beta)$-style "ideal interval" reasoning for IDM3/IDM4 beyond citing prior work (Section 2.3.3–2.3.4) — these are presented as background/baseline methods rather than derived in this paper, so I did not attempt to verify their derivations, only reproduced the formulas as given.
- The claim that indirect (transformation-based) methods "lose interval information" (Section 1, motivating their direct approach) is asserted rather than empirically demonstrated anywhere in the paper — no experiment in the paper directly compares an indirect/transformation baseline (like SetGA, which is arguably closest to that category) against IMEA-IED on an information-loss metric; the comparisons are all on IIGD/Spread/Imprecision/Runtime, which measure downstream solution quality, not information loss per se. This is worth being skeptical of for your project, since your φ-transformation approach is exactly the kind of method being critiqued.
- The optimal parameter $\gamma=0.9$ recommendation (Section 4.4.1) is based on a Wilcoxon test showing $\gamma=0.9$ beats $\gamma=0.5$ in 23/60 and 19/60 cases respectively (IIGD, Imprecision) — note this means it does *not* significantly beat $\gamma=0.5$ in roughly 2/3 to 3/4 of cases either; "best of the values tried" is being reported somewhat more confidently than the raw win-rate supports.
- Sections 3.3–3.4 (niche selection details, complexity analysis) were skimmed per your instructions rather than fully verified line-by-line; the complexity claims ($O(2mN)$, $O(mN^2)$, etc.) are stated but not derived or empirically validated against measured runtimes in the paper.
